# Auto-Parse Prefix by Preset（按预设自动设置自动解析的前后缀）

一个 SillyTavern 第三方扩展：**切换「聊天补全预设」时，自动改写「AI 响应格式 → 推理」里
「自动解析（Auto-Parse）」的前缀 / 后缀（以及分隔符、开关）。**

解决的问题：不同模型的思考块标签不一样（`&lt;think&gt;…&lt;/think&gt;`、`&lt;thinking&gt;…&lt;/thinking&gt;`、
`&lt;reasoning&gt;…&lt;/reasoning&gt;` …，很多预设还会用自定义标签），而 ST 的自动解析前后缀是**全局唯一**的一组设置。
以前每换一个模型都要手改一遍，现在可以按预设名自动切换，也可以让扩展**直接读当前预设的提示词自动推断**。

---

## 功能

前后缀有两个来源，优先级从高到低：**规则 → 自动识别**（都不命中就保持现状，不做任何改动）。

**规则（显式、优先级最高）**

- 平时不需要手写：点候选里的「采用」会自动生成一条按预设名精确匹配的规则
- 每条规则 = 匹配方式 + 匹配内容 + 自动解析开关 + 前缀/后缀/分隔符 + 备注，可在面板里直接改
- 匹配方式：包含 / 完全相同 / 通配符（`*` `?`）/ 正则表达式，均忽略大小写
- 规则自上而下匹配，**第一条命中的生效**；可用 ↑ ↓ 调整顺序
- 规则里留空的 **前缀 / 后缀 / 分隔符** 表示「不修改」，只套用填写了的内容

**自动识别（读当前预设的提示词自己判断）**

- 切换预设时读取**当前聊天补全预设的提示词全文**，找出思维链块的开闭标签，
  例如预设里写了「reasoning steps wrapped in `<thought></thought>` tag」或
  `{{setvar::story_think_format:: <story_driver>...</story_driver> }}`，
  就会把对应的前后缀写进 ST 的自动解析设置
- **只读思维链条目**，按可信度分档，取最高一档（都不满足就**什么都不改**）：
  1. 名字（去掉开头 emoji/符号后）**开头就是**思维链词 + 条目已启用 —— 如「思维链动态开场」「📌 COT 接收」
  2. 同上，但条目没有启用状态信息
  3. 名字里含思维链词且主题不冲突 + 已启用 —— 如「📍常规创作思维」
  4. 同上，但没有启用状态信息
  5. 都没有时，才用「内容里明确写了『把思考包在 X 里』」的条目
- **排除这些干扰**（真实预设里最常见的几类）：
  - **反思维链条目**：用途是**掐掉**模型原生思维链的预填充，例如「🧷卡原生思维链-预填充」里
    其实是 `</think>` `</thinking>` `</story_driver>` 这些收尾标记，「DS-预填充」是 ``。
    判据：名字含 `卡原生/禁用/🈲/anti-think`、内容**只有闭合标记没有开标记**、或带 `<|no-trans|>`
  - **主题不符的条目**：名字里是「NSFW / 破甲 / 开关 / 格式 / 输出顺序 / 状态栏 / 世界书 /
    表情包 / 内心话 / 心声 / 文风 / 语言 …」的条目（除非名字开头就是思维链词）
  - **「NPC 内心话 / 心声 / 独白」这类展示用条目**：它们是写给玩家看的正文内容，不是思维链 ——
    `内心 / inner / monologue` 不再算思维链关键词
  - **预设里内嵌的 `extensions`（正则脚本等）**：不是提示词正文，跳过
  - **STscript 宏**、**`_format` 格式外壳**、**结构性标签黑名单**（`<content>` `<user>` `<wlog>`
    `<npc_log>` `<worldInfo>` `<emoji>` …）
- **未启用的条目会被降档**：同一档里优先选「当前 prompt_order 里启用」的条目 —— 很多预设用
  「多选一」，未启用的那些只是备选（踩过：MoM 选了未启用条目里的 `<think>`，实际启用的
  接收条目用的是 `<ECoT>`）
- **开闭标记可以跨条目**：有些预设把开始写在「思维链动态开场」、结束写在「思维链收尾」
  （如智脑-Z 的 `<脑内会议>`）—— 只要两边都在思维链条目里就认
- 不跨条目乱配：非思维链条目里的开标记不会和别处的闭合标记硬凑成一对
- 打分还会看：**标签名是否与思维链相关** + **同一行是否写明包裹方式**（判断前会剥掉标签与宏本身）
  + **开闭成对还是单边** + 条目相关度档位
- 报告里列出候选（标签、前后缀、得分、来源条目、是否未启用），点 **「采用」** 即写入 ST 的
  自动解析设置，并**自动记成一条按预设名精确匹配的规则** —— 以后切回这个预设永远是这一组
- **都不命中时什么都不做**：不会改你的前后缀，也不会有弹窗；只有控制台 `[AutoParsePreset]` 日志

**触发时机**：切换聊天补全预设、切换聊天、切换主 API、加载设置、ST 启动完成后

## 安装

1. 把整个文件夹复制到 ST 的用户数据目录下的 `extensions/` 里：

   ```
   <SillyTavern>/data/<你的用户名>/extensions/reasoning-autoparse-preset/
   ├── manifest.json
   ├── index.js                  # 事件接线 + 设置面板
   ├── rules.js                  # 规则匹配/校验/导入导出（零依赖纯逻辑）
   ├── detect.js                 # 从预设文本推断思维链标签（零依赖纯逻辑）
   ├── settings.html
   ├── style.css
   └── test/
       ├── rules.test.mjs        # 规则逻辑单测
       ├── detect.test.mjs       # 识别逻辑单测
       └── integration/          # jsdom 集成测试（mock + run.mjs，不参与 ST 运行）
   ```

   单用户默认安装就是 `<SillyTavern>/data/default-user/extensions/`。
   文件夹名可以随便改（扩展会从自身 URL 推断目录名）。

2. 刷新 ST 页面（或重启），打开 **扩展（Extensions）** 面板，展开
   **「自动解析前后缀 · 跟随聊天补全预设」**。

3. 确认 ST 的 **AI 响应格式 → 推理** 区域里 **Auto-Parse（自动解析）** 是开启状态。
   本扩展只负责改前缀/后缀和开关值，不会替你打开 ST 的推理功能。

> 也可以把仓库推到 GitHub，用 ST 的 **扩展 → 安装扩展（Install extension）→ 填 Git URL** 安装。

## 使用

1. 保持 **「自动识别」** 勾选（默认开启），然后正常切换 **聊天补全预设**。
2. 状态栏会告诉你结果：
   - `已按预设「X」从思维链条目识别：前缀 "…"，后缀 "…"` —— 识别成功并已写入 ST 的自动解析设置
   - `也没在思维链条目里找到成对标签，保持当前设置不变` —— 预设里没有思维链条目，什么都不会改
3. 报告区列出候选（标签、前后缀、得分、来源条目）。**点某条候选的「采用」** 即写入设置，
   并自动记成一条按预设名精确匹配的规则 —— 之后切回这个预设永远用这一组。

想手动指定时：点规则区的 **＋** 新建一条，填匹配方式 / 匹配内容 / 前后缀，勾上启用即可。
规则一旦命中，就**不会再**走自动识别。

**匹配的是「聊天补全预设」的名字**，也就是 ST 顶部「预设」下拉里显示的文本
（`#settings_preset_openai`）。

## 面板长什么样

就这么多，没有二级菜单：

```
[✓]启用   [✓]自动解析   [✓]自动识别   [立即应用]
状态：已按预设「X」从思维链条目识别：前缀 "…"，后缀 "…"
候选（最多 3 条，每条一个「采用」按钮）
规则（点「采用」会自动生成，可改可删）                        [＋]
```

- **启用**：总开关（切预设时自动设置前后缀）
- **自动解析**：直接开关 ST 的「推理 → 自动解析」（写 `power_user.reasoning.auto_parse`）；
  关掉后前后缀仍会跟随预设更新，只是 ST 不再拿它解析推理块
- **自动识别**：只读预设里的思维链条目来推断前后缀
- **立即应用**：按当前预设重新跑一次识别并应用

没有任何弹窗提醒（日志在控制台 `[AutoParsePreset]`）。

## 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 状态栏显示「当前主 API 不是聊天补全，已跳过」 | 本扩展只按聊天补全预设工作；请把主 API 切到「聊天补全」 |
| 自动识别不出标签 | 预设里没有名字含思维链的条目，也没有「把思考包在 X 里」这类说明。此时什么都不会改，用规则区的 **＋** 手动建一条即可 |
| 识别到的是 `</think>` 这种预填充标签 | 已修（v1.3.0）：「卡原生思维链」这类**压制原生思维链**的条目会被整条排除 |
| 识别到 NPC 内心话 / 心声的标签 | 已修（v1.4.0）：`内心/心声/独白/inner` 不再算思维链关键词，这类展示用条目会被跳过 |
| 识别到未启用条目里的标签 | 已修（v1.4.0）：同一档里优先「当前 prompt_order 里启用」的条目（MoM、日月西就是踩了这个坑） |
| 识别出的标签不对 | 看报告：正确的那组若在候选里，点它右边的 **「采用」**（会记住）；都不对就用 **＋** 手写一条 |
| 装了新版但行为没变 | ST 用的是 `data/<user>/extensions/` 里的**副本**，GitHub 上的更新不会自动生效 —— 见下面「更新扩展」 |
| 规则没命中 | 检查预设名拼写；匹配内容留空或规则停用都会导致不命中；可先用「包含 + 关键词」最宽松地试 |
| 前后缀改了但模型思考块没被解析 | ST 的自动解析要求**前缀和后缀都非空**；且 ST 用的是 `startsWith` 字面量匹配，标签必须和模型输出完全一致 |
| 「推理模板」下拉名字没跟着变 | 正常。ST 只保存一个模板名，实际参与解析的是 `power_user.reasoning.prefix/suffix`；下拉显示旧模板名不影响解析。 |
| 想看详细日志 | 浏览器控制台过滤 `[AutoParsePreset]` |

## 更新扩展

GitHub 上的提交**不会**自动同步到你 ST 里的副本，要手动覆盖一次：

1. 用 ST 的 **扩展 → 安装扩展** 重新填一次 Git URL（会重新拉取），或者
2. 手工把 `data/<你的用户名>/extensions/reasoning-autoparse-preset/` 里的
   `index.js / detect.js / rules.js / settings.html / style.css / manifest.json` 换成新版本，然后刷新页面。

装好后在 **扩展** 面板里能看到版本号（当前 **1.5.0**）；控制台里 `[AutoParsePreset] loaded as …`
也会打印一行。

## 与 ST 原生能力的关系

ST 原生的「推理模板（Reasoning Formatting）」下拉，在你**手动选择模板时**会套用模板里的
前后缀 —— 但它和「聊天补全预设」没有任何绑定。本扩展补的正是这一环：
**预设 → 前后缀** 的自动映射，外加**直接读预设提示词做推断**。

## 实现要点（给想改代码的人）

- 写入的目标：`power_user.reasoning.auto_parse / prefix / suffix / separator`
  （见 `public/scripts/reasoning.js`）
- 自动识别的数据源：`getChatCompletionPreset()`（`public/scripts/openai.js`），
  即当前聊天补全预设的完整正文（含 `prompts` / `prompt_order` 等）
- 同时更新界面控件 `#reasoning_auto_parse / #reasoning_prefix / #reasoning_suffix / #reasoning_separator`，
  并 `saveSettingsDebounced()` 持久化
- 监听事件：`OAI_PRESET_CHANGED_AFTER`、`CHAT_CHANGED`、`MAIN_API_CHANGED`、
  `SETTINGS_LOADED_AFTER`、`APP_READY`
- `rules.js` / `detect.js` 都是零依赖纯逻辑，可离线测试：

  ```bash
  node test/rules.test.mjs     # 23 项：匹配/校验/导入导出/模板常量
  node test/detect.test.mjs    # 36 项：标签推断、思维链条目分档、反思维链排除、文本收集
  cd test/integration && pnpm install && node run.mjs   # 39 项：事件接线 + 面板交互 + 自动识别
  ```

- 扩展自身的设置存在 `extension_settings.reasoningAutoParsePreset`
  （`enabled` / `autoParse` / `autodetect` / `rules` / `lastDetected`；
  旧的 `extraText` 若残留仍会被识别流程使用）

## 已知限制

- 只跟随**聊天补全预设**；文本补全（Text Completion）预设不参与匹配
- 自动识别只读**当前预设的提示词文本**（`prompts` 等）：如果某个预设的思维链格式只写在
  ST 的**正则脚本**或世界书里，识别不到 —— 手动建一条规则即可（`extension_settings.reasoningAutoParsePreset.extraText`
  里写了文本也仍会被识别流程使用）
- 只读**思维链条目**：预设里没有名字含思维链的条目时，只在「内容明确写了包裹方式」
  的条目里找；两者都没有就完全不改。这是刻意的保守策略（宁可不改也不改错）
- 自动识别需要预设里出现**成对标签**；只有「用自然语言描述思考过程」而没有标签的预设，
  识别不出（这类预设本来也没法用自动解析）
- **多块思维链的预设会有多个合理答案**（例如同时存在 `<脑内会议>` 与 `<thinking_left>`，
  或 `<story_driver>` 与 `<acg_think>`）。扩展按「思维链条目分档 + 打分」挑一个，
  报告里列出前 3 个候选，点 **「采用」** 即可换成你要的那组并永久记住
- 「只出现开标记」的标签只在报告里显示、不自动套用（闭合标签靠推断，风险偏高），
  需要时建一条规则把前后缀手填完整
- 判定「反思维链」条目用的是名字关键词 + 「只有闭合标记没有开标记」+ `no-trans` 三条启发式；
  极端命名的预设可能需要建规则手工兜底
- 「分隔符」留空会被当成「不修改」，无法用它把分隔符清空
- 正则在预设名上测试（大小写不敏感），不支持跨字段匹配
